# Contributing

Listing a skill here is an endorsement. Anyone who runs
`/plugin install <skill>@trycopilotai` is handing an
instruction set to an agent that will act on their machine
and inside their repository. The bar reflects that.

## The bar for listing

A skill is listed once all of these are true.

**It has a home repository.** Issues, releases, and examples
live there. This catalogue points at it.

**Its `description` says what it does and when to use it.**
This is the only field loaded at startup for every installed
skill, so it is what the agent matches against when deciding
whether to activate. A description that describes the skill
but not its trigger will not fire.

**It has at least one worked example**, produced by running
the skill rather than written by hand, with a manifest
recording the agent, version, input, and date.

**Its side effects are declared.** The `meta/` entry records
`writes`, `network`, and `executes`. A skill that reads and
reasons is a different risk than one that runs commands, and
an adopter should not have to read the prompt to find out
which they are getting.

**It treats what it reads as evidence, not instruction.** A
skill that processes repository content is a prompt-injection
surface. If a hostile `AGENTS.md` or code comment can change
what the skill does, it is not ready.

**It has a license**, both in the home repository and in the
`meta/` entry.

**It is pinned.** Remote sources carry a `ref` or a `sha`.
Never a mutable default branch, because a future upstream
commit would silently change what a user's agent is told to
do.

## Adding one

1. Create `meta/<name>.skill.yml`. Copy an existing entry for
   the field set.
2. Add the plugin under `plugins/<name>/` with a
   `.claude-plugin/plugin.json` and
   `skills/<name>/SKILL.md`, or point `source` at the
   upstream repository if it carries its own plugin manifest.
3. Add the entry to `.claude-plugin/marketplace.json`.
4. Run `make check`. It validates the catalogue, the plugin
   manifests, every `SKILL.md` against the Agent Skills spec,
   and vendor drift, then confirms the generated index is
   current.
5. Commit `meta/`, the plugin, and the regenerated
   `catalogue.json` and `INDEX.md` together.

Never hand-edit `catalogue.json` or `INDEX.md`. They are
generated by `make catalogue`.

## Renaming or removing

Do not delete an entry outright. Add the old name to the
`renames` map in `marketplace.json`, mapped to the new name,
or to `null` if the skill is gone. Existing users then
migrate on their next `/plugin marketplace update` instead of
hitting an error.

## Skill authoring notes

Keep `SKILL.md` under 500 lines. Agents load the whole body
on activation, so detail belongs in `references/` beside it,
loaded only when needed.

The `name` field must match its directory name, use lowercase
letters, numbers, and single hyphens, and stay under 64
characters. `make validate` checks all of it.

## Style

Prose wraps at 60 columns. Do not use dashes as punctuation.
Use a comma, a colon, parentheses, or a new sentence. Hyphens
inside compound words are fine.
